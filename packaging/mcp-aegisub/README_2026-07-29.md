# Aegisub MCP

把 Aegisub 的字幕编辑能力暴露为 [Model Context Protocol](https://modelcontextprotocol.io) 服务，
供 Claude Desktop / Cursor / 其他支持 MCP 的 AI 客户端调用。

## 架构

```
用户双击 Aegisub → 正常 GUI 启动 → 内嵌 MCP HTTP server 监听 127.0.0.1:7878
                                          ↑
                                          │ HTTP/SSE (JSON-RPC 2.0)
                                    AI 客户端(Claude Desktop 等)
```

- **用户和 AI 操作同一个 Aegisub 实例**，AI 做的修改在 GUI 中实时可见
- 用户可以看到 AI 编辑字幕、修改样式、移动时间轴等所有操作
- 不需要特殊的启动参数，Aegisub 正常启动就自带 MCP 服务
- 支持多个 AI 客户端同时连接（Claude Desktop + Cursor 一起用）

## 协议说明

MCP 服务使用 **Streamable HTTP 传输**（MCP 规范 2024-11-05），
通过 HTTP POST 请求交换 JSON-RPC 2.0 消息。

- 当前实现采用**简单请求-响应模式**：AI 客户端 POST JSON 请求，服务器返回 JSON 响应
- 暂不支持 SSE（Server-Sent Events）流式推送，因为 Aegisub 的工程变更通知机制
  与 MCP 通知系统的桥接需要额外实现
- 如果需要 SSE 支持，后续可扩展 `POST /mcp` 端点在响应头返回 `Content-Type: text/event-stream`

### 关于 `run_command` 与 Aegisub 全部命令

Aegisub 内置 100+ 已注册命令（见 `docs/hotkey_commands.md`），涵盖：
- 字幕文件: `subtitle/open`、`subtitle/save`、`subtitle/new`、`subtitle/close`
- 音频: `audio/open`、`audio/close`
- 视频: `video/open`、`video/close`
- 编辑: `edit/line/cut`、`edit/line/copy`、`edit/line/paste`
- 时间调整: `time/shift`、`time/scale`、`time/frame/current`
- 网格: `grid/line/insert`、`grid/line/duplicate`
- 等

**`run_command` 工具可以直接调用所有这些命令**，例如：
```json
{"command": "run_command", "arguments": {"command": "subtitle/open"}}
{"command": "run_command", "arguments": {"command": "audio/open"}}
{"command": "run_command", "arguments": {"command": "time/shift"}}
```

但注意使用 `run_command("subtitle/open")` 会弹出文件选择对话框，阻塞 AI 调用。
**推荐使用专用的 `open_file`、`save_file`、`new_file` 工具**，它们直接操作文件路径，无需 GUI 交互。

### 专用工具 vs `run_command` 的选择建议

| 场景 | 推荐方式 | 原因 |
|---|---|---|
| 打开文件 | `open_file(path)` | 直接指定路径，无对话框 |
| 保存文件 | `save_file(path?)` | 直接指定路径，无对话框 |
| 新建文件 | `new_file()` | 无参数，直接创建 |
| 修改字幕字段 | `update_subtitle_fields(...)` | 结构化参数，AI 易理解 |
| 调整时间轴 | `shift_times(...)` | 结构化参数 |
| 其他非阻塞命令 | `run_command(...)` | 通用网关，100+ 命令全覆盖 |

### `run_command` 阻塞命令清单

以下命令会弹出 GUI 对话框，**阻塞 AI 调用**，应避免通过 `run_command` 使用：

| 文件对话框 | `subtitle/open`, `subtitle/save/as`, `subtitle/close`, `audio/open`, `video/open` |

| 编辑对话框 | `subtitle/find`, `edit/font`, `edit/find_replace` |

以下命令**安全不阻塞**，可直接通过 `run_command` 调用：

|---|---|
| 行操作 | `edit/line/copy`, `edit/line/cut`, `edit/line/paste`, `edit/line/duplicate` |
| 网格导航 | `grid/line/next`, `grid/line/prev`, `grid/line/insert/after`, `grid/line/insert/before` |
| 音频播放 | `audio/play/line`, `audio/stop`, `audio/commit` |
| 视频播放 | `video/next_frame`, `video/prev_frame`, `video/play`, `video/stop` |
| 时间调整 | `time/shift`, `time/frame/current`, `time/scale` |
| 样式切换 | `edit/style/bold`, `edit/style/italic`, `edit/style/underline` |
| 显示模式 | `app/display/audio_subs`, `app/display/full`, `app/display/subs`, `app/display/video_subs` |

## 安装与使用

无需额外安装步骤。Aegisub 一启动就自带 MCP 服务。
默认配置 `App/MCP/Enabled = true`，HTTP 端口 `7878`，监听 `127.0.0.1`。

## AI 客户端配置

### Claude Desktop

编辑 `%APPDATA%\Claude\claude_desktop_config.json`：

```json
{
  "mcpServers": {
    "aegisub": {
      "type": "url",
      "url": "http://127.0.0.1:7878/mcp"
    }
  }
}
```

### Cursor

在 `~/.cursor/mcp.json` 中加入：

```json
{
  "mcpServers": {
    "aegisub": {
      "type": "url",
      "url": "http://127.0.0.1:7878/mcp"
    }
  }
}
```

> 注意：MCP 的 HTTP 模式需要客户端支持 `type: "url"` 的配置方式。
> 如果客户端只支持 stdio，可以保留旧的 `--mcp` 模式，但更适合的用法是
> 直接通过 HTTP 连接运行中的 Aegisub 实例。

### 手动测试

用 curl 测试 MCP 服务是否正常：

```bash
# 初始化
curl -s -X POST http://127.0.0.1:7878/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'

# 列出工具
curl -s -X POST http://127.0.0.1:7878/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'

# 调用工具
curl -s -X POST http://127.0.0.1:7878/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"get_project_info","arguments":{}}}'
```

## 工作流示例

1. 用户双击 Aegisub 正常启动
2. AI 客户端通过 HTTP 连接 Aegisub 的 MCP 服务
3. AI 调用 `get_project_info` 了解当前工程状态
4. AI 调用 `update_subtitle_lines` 修改字幕行
5. 用户在 Aegisub GUI 中实时看到 AI 的修改
6. 用户可以随时在 GUI 中撤销 AI 的修改（Ctrl+Z）

## 架构设计（与旧方案对比）

### 旧方案（stdio 模式，已废弃）

```
AI 客户端 ──stdio──> Aegisub --mcp 子进程（无 GUI，两个实例数据不同步）
```

问题：
- 子进程没有 GUI 界面，用户看不到 AI 做了什么
- 用户手动启动的 Aegisub 实例和 AI 拉起的实例数据不同步
- 一个 AI 客户端独占一个进程

### 新方案（SSE/HTTP 模式，当前实现）

```
AI 客户端 ──HTTP──> 已运行的 Aegisub（带 GUI，实例共享）
```

优势：
- 用户和 AI 操作同一个实例，实时可见
- 不需要特殊启动参数
- 支持多个 AI 客户端同时连接
- 用户可以在 GUI 中干预 AI 的操作

## 配置

通过 Preferences 或直接修改 `default_config.json` 配置：

```json
"App" : {
  ...
  "MCP" : {
    "Enabled" : true,
    "Host" : "127.0.0.1",
    "Port" : 7878
  }
}
```

## 协议细节

MCP 协议实现遵循 Streamable HTTP 传输规范：

- 端点：`POST /mcp`
- 请求体：JSON-RPC 2.0 请求对象
- 响应体：JSON-RPC 2.0 响应对象
- Content-Type：`application/json`
- 支持 CORS 预检请求

## 目录结构

```
libaegisub/include/libaegisub/mcp/server.h   # MCP server 公共接口
libaegisub/common/mcp/server.cpp              # JSON-RPC 分发 + HTTP 传输层(boost::asio)
src/mcp_server.h / src/mcp_server.cpp          # Aegisub 工具注册（3 个骨架 tool）
src/main.cpp + src/main.h                      # 启动时 spawn HTTP server 线程
src/libresrc/default_config.json               # MCP 默认配置
```
