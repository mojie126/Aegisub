# Aegisub MCP

把 Aegisub 的字幕编辑能力暴露为 [Model Context Protocol](https://modelcontextprotocol.io) 服务，
供 Claude Desktop / Cursor / 其他支持 MCP 的 AI 客户端调用。

## 架构

```
用户双击 Aegisub → 正常 GUI 启动 → 内嵌 MCP HTTP server 监听 127.0.0.1:7878
                                          ↑
                                          │ HTTP/SSE (JSON-RPC 2.0)
                                    AI 客户端(Claude Desktop 等)
```

- **用户和 AI 操作同一个 Aegisub 实例**，AI 做的修改在 GUI 中实时可见
- 用户可以看到 AI 编辑字幕、修改样式、移动时间轴等所有操作
- 不需要特殊的启动参数，Aegisub 正常启动就自带 MCP 服务
- 支持多个 AI 客户端同时连接（Claude Desktop + Cursor 一起用）

## 协议说明

MCP 服务遵循 **MCP 规范 2024-11-05**，同时支持两种 HTTP 传输（JSON-RPC 2.0）：

| 传输方式     | 端点                                              | 说明                                           |
|----------|-------------------------------------------------|----------------------------------------------|
| 无状态 POST | `POST /mcp`（任意路径均可）                             | 请求-响应单次完成，适合 curl 手动测试与简单客户端                 |
| HTTP+SSE | `GET /sse` 建连，`POST /message?sessionId=xxx` 发消息 | 长连接，响应经 SSE `message` 事件推送，标准 MCP 客户端的常规连接方式 |

- 两种传输同时可用，互不影响，同一 Aegisub 实例可同时服务多种客户端
- SSE 连接每 30 秒发送心跳注释保活，客户端断开后会话自动清理
- 响应经 SSE 推送时统一压缩为单行 JSON，兼容按行解析的客户端

### 关于 `run_command` 与 Aegisub 全部命令

Aegisub 内置 272 个已注册命令（见 `docs/hotkey_commands.md`），涵盖：

- 字幕文件: `subtitle/open`、`subtitle/save`、`subtitle/save/as`、`subtitle/new`、`subtitle/close`
- 音频: `audio/open`、`audio/close`、`audio/play/line`、`audio/stop`
- 视频: `video/open`、`video/close`、`video/frame/next`、`video/frame/prev`
- 编辑: `edit/line/cut`、`edit/line/copy`、`edit/line/paste`、`edit/line/duplicate`
- 时间调整: `time/shift`、`time/frame/current`、`time/snap/scene`
- 网格: `grid/line/next`、`grid/line/prev`、`grid/sort/text`
- 等

**`run_command` 工具可以直接调用所有这些命令**，MCP 客户端示例：

```json
[
	{
		"name": "run_command",
		"arguments": {
			"command": "subtitle/open"
		}
	},
	{
		"name": "run_command",
		"arguments": {
			"command": "audio/open"
		}
	},
	{
		"name": "run_command",
		"arguments": {
			"command": "time/shift"
		}
	}
]
```

`run_command` 返回 `executed` 字段：`true` 表示命令的 Validate 校验通过且已调用；
`false` 表示前置条件不满足（如无视频/音频/选中行）未执行；命令名不存在时返回错误，
并附带相近命令建议（如 `did you mean: ...`）与 `list_commands` 查询提示。

注意命令名必须准确，例如 `video/frame/next`、`video/frame/prev`（不是 `video/next_frame`）。
不确定命令名时，先调用 `list_commands` 获取全部有效命令名、阻塞标记与专用工具映射。

但注意使用 `run_command("subtitle/open")` 会弹出文件选择对话框，阻塞 AI 调用。
**推荐使用专用的 `open_file`、`save_file`、`new_file` 工具**，它们直接操作文件路径，无需 GUI 交互。

## 安装与使用

无需额外安装步骤。Aegisub 一启动就自带 MCP 服务。
默认配置 `App/MCP/Enabled = false`（需在偏好设置中启用），HTTP 端口 `7878`，监听 `127.0.0.1`。

## AI 客户端配置

标准 MCP 客户端（Claude Desktop 等）推荐使用 SSE 端点 `http://127.0.0.1:7878/sse`
若客户端采用无状态 HTTP 模式，则填 `http://127.0.0.1:7878/mcp`
两种方式均可

### Claude Desktop

编辑 `%APPDATA%\Claude\claude_desktop_config.json`：

```json
{
	"mcpServers": {
		"aegisub": {
			"type": "url",
			"url": "http://127.0.0.1:7878/sse"
		}
	}
}
```

### Cursor

在 `~/.cursor/mcp.json` 中加入：

```json
{
	"mcpServers": {
		"aegisub": {
			"type": "url",
			"url": "http://127.0.0.1:7878/sse"
		}
	}
}
```

> 注意：MCP 的 HTTP 模式需要客户端支持 `type: "url"` 的配置方式。
> 如果客户端只支持 stdio，可以保留旧的 `--mcp` 模式，但更适合的用法是
> 直接通过 HTTP 连接运行中的 Aegisub 实例。

### 手动测试

用 curl 测试 MCP 服务是否正常：

```bash
# 无状态 POST /mcp
# 初始化
curl -s -X POST http://127.0.0.1:7878/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'

# 列出工具
curl -s -X POST http://127.0.0.1:7878/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'

# 调用工具
curl -s -X POST http://127.0.0.1:7878/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"get_project_info","arguments":{}}}'
```

SSE 模式手动测试（两个终端）：

```bash
# 终端 1: 建立 SSE 长连接, 收到 event: endpoint, 记录其中 /message?sessionId=xxx
curl -N http://127.0.0.1:7878/sse

# 终端 2: 向消息端点发请求, 响应在终端 1 中以 event: message 推送
curl -s -X POST http://127.0.0.1:7878/message?sessionId=s0 \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

## 工作流示例

1. 用户双击 Aegisub 正常启动
2. AI 客户端通过 HTTP 连接 Aegisub 的 MCP 服务
3. AI 调用 `get_project_info` 了解当前工程状态
4. AI 调用 `update_subtitle_fields` 修改字幕行
5. 用户在 Aegisub GUI 中实时看到 AI 的修改
6. 用户可以随时在 GUI 中撤销 AI 的修改（Ctrl+Z）

## 架构设计（与旧方案对比）

### 旧方案（stdio 模式，已废弃）

```
AI 客户端 ──stdio──> Aegisub --mcp 子进程（无 GUI，两个实例数据不同步）
```

问题：

- 子进程没有 GUI 界面，用户看不到 AI 做了什么
- 用户手动启动的 Aegisub 实例和 AI 拉起的实例数据不同步
- 一个 AI 客户端独占一个进程

### 新方案（SSE/HTTP 模式，当前实现）

```
AI 客户端 ──HTTP──> 已运行的 Aegisub（带 GUI，实例共享）
```

优势：

- 用户和 AI 操作同一个实例，实时可见
- 不需要特殊启动参数
- 支持多个 AI 客户端同时连接
- 用户可以在 GUI 中干预 AI 的操作


## 协议细节

MCP 协议实现遵循 2024-11-05 规范，支持无状态 HTTP 与 HTTP+SSE 两种传输：

- 无状态端点：`POST /mcp`（任意路径均可），请求体/响应体均为 JSON-RPC 2.0 对象
- SSE 端点：`GET /sse` 建立长连接，服务器发送 `event: endpoint` 事件，
  `data` 为消息端点 `/message?sessionId=xxx`；客户端向该端点 `POST` JSON-RPC 请求，
  服务器处理完毕后返回 `202 Accepted`，响应经 SSE `event: message` 事件推送
- 会话上限 16 个，超出返回 503；无效 sessionId 返回 404，缺 sessionId 返回 400
- Content-Type：`application/json`（SSE 为 `text/event-stream`）
- 支持 CORS 预检请求

## 错误处理

工具调用失败时返回 JSON-RPC error（code -32603），`message` 为具体原因：

| 场景              | 行为                                                                                                                                                                                                                                                  |
|-----------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 命令/样式/行不存在      | 明确报错；`run_command` 命令名不存在时附带相近命令建议（`did you mean: ...`）与 `list_commands` 查询提示，<br/>如 `'edit/toggle_comment' is not a valid command name, did you mean: ...? use list_commands to query all valid command names`；<br/>样式/行不存在，如 `style not found: X` |
| 参数缺失/非法         | 明确报错，如 `missing 'path'`、`invalid color value`                                                                                                                                                                                                       |
| 文件不存在           | `File not found: <path>`                                                                                                                                                                                                                            |
| 视频/音频格式不支持      | 汇总各 provider 失败原因后报错（非交互模式，不弹 GUI 对话框）                                                                                                                                                                                                              |
| Validate 未通过的命令 | `run_command` 返回 `executed: false`（不报错）                                                                                                                                                                                                             |
| 内部异常            | `agi::Exception`/`std::exception` 消息透传                                                                                                                                                                                                              |

## 交互式对话框的处理策略

Aegisub 的 GUI 加载链路（provider 选择、错误提示、进度、分辨率不匹配等）会弹出
**模态对话框**，若在 MCP 调用中触发会阻塞请求直至用户手动点击。处理策略：

1. **一律以非交互模式（`interactive=false`）驱动加载链路**：`open_video`/`open_audio`
   不弹 provider 选择框、错误框、进度框，异常直接转 JSON-RPC 错误
2. **分辨率不匹配不弹窗也不自动修改**：`open_video` 返回
   `video_width/height`、`script_width/height` 与 `resolution_mismatch` 字段，
   AI 据此判断；需要调整时用 `set_script_resolution(width, height)` 显式修改
   （对应 GUI 中"修改字幕分辨率"对话框的决策由 AI 替代）
3. **需要用户拍板的操作应避免**：如 `run_command` 调用 `subtitle/find`、
   `edit/font` 等弹窗命令会阻塞，`list_commands` 返回的 `blocking` 标记、
   工具描述与本文档已明确标注

### 已知会弹窗的剩余场景（无法从 MCP 侧消除）

| 触发                                                            | 弹窗                                                      | 处理建议                          |
|---------------------------------------------------------------|---------------------------------------------------------|-------------------------------|
| `open_file` 打开 .mkv/.mka 等多轨容器                                | 轨道选择框                                                   | 用户在 GUI 中选择                   |
| 多音轨/多视频轨文件 `open_audio`/`open_video`（FFmpegSource）            | "Choose audio/video track" 框                            | 用户在 GUI 中选择                   |
| GUI 打开带 `[Aegisub Project Garbage]` 段且含关联视频路径的 .ass（仅 GUI 路径） | "(Un)Load files?" 确认框（当 `App/Auto/Load Linked Files=2`） | 用户在 GUI 中确认；或先清理文件的 Garbage 段 |

## 进程崩溃与 MCP 的边界

**MCP 的异常处理（`agi::Exception`/`std::exception` 捕获 → JSON-RPC error）
只能覆盖可抛出的 C++ 异常。进程级崩溃（如 0xC0000005 访问违例）是 SEH/OS 级异常，
不经 C++ catch 链，Aegisub 的 crash writer 写 minidump 后进程退出，
MCP HTTP 连接断开（客户端收到 502/连接重置），**无法恢复，只能重启 Aegisub**。

**已修复的崩溃 bug**（排查过程中发现并修复，GUI 手动操作与 MCP 操作走同一路径，共同受益）：

1. **`SubsController::Close()` 悬空 selection 与网格缓存**：`Close()` 中 `swap` 旧字幕文件后，
   `Commit("")` 的信号链会访问已移出 Events 的行。修复：**先 Commit（触发 `BaseGrid::UpdateMaps`
   重建行缓存）再 `SetSelectionAndActive` 切到新行**。
2. **MCP `open_file` 未更新选中行（最终残留崩溃根因）**：MCP 直接调用 `subsController->Load()`，
   漏掉 GUI `DoLoadSubtitles` 末尾的 `SetSelectionAndActive`，`Load` 内部 `swap`+析构会
   `delete` 旧行对象，`SubsEditBox::line` 等组件缓存悬空，后续 `new_file` 的 Commit 信号链
   读取悬空指针崩溃（CLion 调试器定位：`SubsEditBox::OnCommit → GetStyle → boost::iequals`
   访问已复用内存）。修复：`open_file` 加载后同步更新选中/活动行。
3. **`SubsController::OnCommit` 空 undo 栈合并**：`Close()`/`Load()` 清空 undo 栈后
   提交空 message 的 Commit，coalescing 分支对空栈 `back()`/`pop_back()`（未定义行为）。
   修复：coalescing 条件加 `!undo_stack.empty()`。
4. **`BaseGrid::ScrollTo` clamp 未定义行为**：网格无可视行（`GetVisRows()==0`）时
   `std::clamp(y, 0, -1)` 的 lo>hi 是 UB。修复：`max_row < 0` 时直接返回。
5. **其他**：`delete_subtitle_line` 删除后重建 selection、`update_style` 字段预验证
   （防部分应用与 intrusive hook 拷贝破坏链表）、`LoadVideo` Freeze/Thaw 泄漏（RAII 守卫）、
   `export_gif` 异常路径句柄泄漏（RAII 清理）。

**关于外部渲染插件（CSRI/VSFilterMod）**：libcsri 仅在 DLL 加载失败时 `FreeLibrary`，
正常加载的渲染器 DLL 常驻进程直到退出，`close_video`/`new_file` 不会卸载插件；
但会调用插件的 `csri_close`（释放字幕实例）。崩溃排查早期曾怀疑插件释放，
实测切换 libass 渲染后崩溃依旧复现，确认与渲染插件无关（根因见上）。
